# Code review: Rebeat, 2026-10-15

A principal-engineer pass over all of `src/`, `electron/` and `public/worklets/` (≈73k lines
outside tests; the tests weren't reviewed or touched). The goal was cleanup: simplify, remove
redundancy and dead code, without new abstraction layers, with latency, speed and robustness
first.

How it was done: nine reviewers read every file of one area each (engine core; synth engine and
patch model; state; model and templates; MIDI, IO, storage, Electron and the app shell; library
and beatbox; two halves of the panels plus components) and one swept the whole repository.
Claims marked **✔** were re-checked by hand against the code; the rest come from careful reads
but weren't independently re-run. Findings that turned out wrong or trivial were dropped.

**Overall:** the architecture holds up well. One project store with commits, an engine that
reconciles, a lookahead scheduler, visuals outside React, a pure model layer. There are no
TODO/FIXME/`@ts-ignore`, no stray `console.log`, and only 4 `: any`. The problems are of three
kinds:

1. **A handful of real bugs**, mostly in rarely exercised paths: redo, tape stop, mic
   monitoring, a timeline cache, MIDI note-offs on Mackie ports.
2. **Avoidable work in hot paths**: the synth's per-sample allocations, rebuilding the knob list
   on every commit, whole-store React subscriptions, per-message zustand updates in MIDI.
3. **Resource lifetimes**: things created per track or per session that are never released
   (warpers, scratch worklets, decoded buffers, held keys across project loads).

## 2. Latency and speed

### Audio thread (synth worklet)

- Everything in #10 above.
- `core.ts:550–562`: `this.events.shift()` in the event loop is O(n), and `queue()` does an O(n)
  insertion. With dense automation (8 ramps per eased step, per path) the queue holds hundreds of
  entries. Use a read index (`head++`) and compact once per `process()`.
- `core.ts:889`: drift calls `Math.random()` per oscillator per voice per block, and discards
  99.8% of the results. Use a countdown per voice instead.
- `core.ts:1162–1168` and `synth.ts:480–489`: macro target paths are `split(".")` on every
  `applyMacros` (main thread) and kept in a never-cleared `split` map (worklet). Store
  `keys: string[]` with the target when the patch is set, or use one shared cache function. See
  also the duplicated path walkers in §3.
- `core.ts:541`: `get active()` uses `filter().length`; it's only used by tests today. Keep a
  counter if anything polls it.

### Scheduler and engine (main thread, per step or per hit)

- `engine.ts:589–591`: every choked drum hit calls `useStore.getState()` and builds a `Set`
  through `filter`/`map`. Build choke-group membership in `reconcile` (it already walks the
  tracks).
- `automation.ts:108–121`: `trackRegions(project)` is computed twice per step (`coveredTracks`
  and `regionStep`) and sorts every time. Cache it on `project.regions` identity in a WeakMap.
- `store.ts:269–274`: `isAudible` scans tracks twice per call and is called per track per step.
  Compute `anySolo` once in `playStep`.
- `transport.ts:247,257`: `nextBeatTime`/`nextBarTime` copy and reverse `history` per call.
  Loop backwards instead.
- `engine.ts:514–518`, `624–626`: `S.voices.indexOf` + `splice` in every `onended`. A `Set`
  makes it O(1) and simplifies `stopAll`/panic.
- `automationOverride.ts:63`: after #8 this is cheap, but add
  `if (s.project.automation === prev.project.automation && s.project.tracks === prev.project.tracks && …) return`
  style fast exits where possible. At minimum, skip when the change is to `patterns` only (step
  edits), which is most commits.

### MIDI input path

- Besides #11: `lastMsgKey` (the duplicate filter, `midi.ts:149–173`) gains a key per distinct
  `type/channel/number/value` and is never pruned. Key it by `type/channel/number` only and store
  the value plus time.
- `midi.ts:460`: `useMidi.getState().learning` per message is fine. Leave it.

### React and canvases

- **Drum machine rows** (`TrackList.tsx:59`, `TrackRow.tsx:112`): `TrackList` subscribes to the
  whole project, and `TrackRow` isn't memoized, so every commit re-renders every row.
  `memo(TrackRow)` helps commits that don't touch the pattern (knob drags, mixer). A step toggle
  makes a new `pattern`, and every row receives `pattern` as a prop. Pass the few fields the row
  reads (`stepCount`, `stepSize`, `swing`, `keyOverride`) instead of the pattern object, so only
  the row whose `lane` changed renders. Also make `geo` stable (memoized). `TrackRow.tsx:124`
  (`flats`) then becomes cheap automatically.
- **Piano roll** (`PianoRollPanel.tsx:120`): subscribes to the whole project for `bpm`,
  `timeSignature`, `key`. Use three selectors.
- **Synth editor**:
  - `useSwitchValue` (`SynthEditorPanel.tsx:2150–2161`) calls `setState` from `onFrame` for every
    automated switch. That's cheap while the value holds, but it renders at every change and shows
    the old lane's value after `auto.live` changes. Reset on change, or write a `data-` attribute
    from the frame callback as `Encoder` does.
  - `live={() => …}` inline arrows (`:464–469`) re-subscribe each Encoder's frame callback on
    every editor render. Memoize per destination.
  - `ShapePicker` (`:1503–1533`, 21 paths per render) and `WavePreview` (`:2027–2064`, 201
    samples per render) recompute on every knob drag. Use `useMemo` on the oscillator fields.
- **Timeline**:
  - `CurveLane.tsx:137–150` samples the curve every 3 px on every render, and gets a new
    `curve` arrow each time (`TrackRows.tsx:200,290`). Memoize the path on
    `[points, width, ppq, min, max]` and pass `resolved` instead of a closure.
  - `TrackRows.tsx:419–441`: `lanesOf` runs per track over all lanes, calling `targetOwner` twice
    per lane. Group lanes by owner once per render (a `Map`).
- **Controller panel** (`MiniLab3Svg.tsx:452–534`): ~100 `querySelector` calls per dirty frame
  (only frames where something changed, so this is medium). Cache the element references once at
  mount.
- **Beatbox**:
  - `RecordingStatus` (`BeatboxPanel.tsx:383–388`) re-renders 20×/s through a `setInterval` whose
    state isn't even read (`void now`). Write the label from `onFrame` into a ref.
  - `RecordingRow` subscribes every row to `voices` (`:307`); read it in the menu callback.
- `SoundSection.tsx:55–62`: `setState(instrumentState(id))` every 400 ms with a new object
  re-renders forever. Bail out when the status hasn't changed, and stop polling once it's loaded.
- Separate `requestAnimationFrame` loops outside `render/raf.ts`: `PerformancePanel.tsx:300`,
  `BeatboxPanel.tsx:432`, `sample-editor/Waveform.tsx:250`. Move the first two onto `onFrame`.

### Startup

What's parsed before the first click, and can wait:

- `engine/instruments.ts` → `library/synths.ts` (91 specs, ~54 KB) is pulled in by the
  always-loaded engine. Import the factory list lazily where a voice is created, or split the
  ids and names (needed by the library list) from the specs.
- `App.tsx` imports all eight dialogs statically. `ExportDialog` brings `engine/render` and
  `library/encode`, `WavetableDialog` brings `model/wavetables`, and `ProjectBrowser` brings
  every template and example. Use `React.lazy` as `panels.tsx` does.
- `defaultCommands.ts` imports `EXAMPLES` and `TEMPLATES` at the top for a few commands. Move
  them into dynamic imports in those `run`s.
- Measure before and after with a bundle visualizer. `vite.config.ts` raised
  `chunkSizeWarningLimit` to 1100, which hides growth; lower it once the chunks are split.

### Library I/O

- `library.ts:58–61`: `refresh()` re-reads the whole `samples` table (with peaks) after every
  single edit, rename, import or delete, and `saveVersion` refreshes twice (`:317`). Update the
  changed records in state; keep the full read for bulk operations.
- `library.ts:377–388`: `samplesInUse` fully deserializes and migrates every saved project
  before removing a folder. Read only the sample ids from the raw JSON.
- `library.ts:394–403` and `beatbox/store.ts:399–407`: sequential `update` calls in loops. Use
  `bulkPut`, then one state update.
- `beatbox/store.ts:108–111`: a windowed-sinc resample of whole recordings on the main thread
  (seconds of jank for long takes). Use an `OfflineAudioContext` at 16 kHz (native resampler),
  or the model worker. Note that onsets must stay identical to `ml/` (AGENTS.md §8), so check
  the parity fixtures if the resampler changes. Otherwise move the same code into a worker.
- `onlineKits.ts:85–106`, `onlineImport.ts`: fetches without a timeout. Use
  `AbortSignal.timeout(…)`. `onlineImport.ts:16–29` keeps every previewed download for the
  session with no cap; add an LRU (count or bytes).

## 4. Robustness

- **Grid controllers never forget a device** (`audio-io/controllers/controllers.ts:123–135`):
  `connected` only grows. After unplugging a Launchpad or Push, every LED update `send()`s to a
  closed port and throws. Prune on `MIDIAccess.onstatechange`. Its `onStep`, `onMidiMessage` and
  `useStore.subscribe` registrations are never undone, so a second `connectControllers()` would
  double them.
- **Upgrading MIDI access to SysEx** (`midi.ts:211–246`) clears every `onmidimessage` before the
  new access arrives. A note-off in that gap leaves a stuck note. Swap handlers after the new
  access resolves.
- **Pitch bend's `value`** (`midi.ts:347`) is `14-bit / 128` (0..127.99) and is ignored
  downstream, which re-reads the raw bytes (`:504–506`). Parse it once to −1..1 and use that.
- **Drags without `pointercancel`**: `CurveLane.tsx:166–284`, `SectionsRow.tsx:133–181`,
  `RegionBox.tsx:107–155`. A cancelled pointer (touch, a system gesture, losing capture) leaves
  the listeners attached. Add `pointercancel` and `lostpointercapture`. This is the place for one
  small shared helper, since the three files repeat the same pattern.
- **Queued mute-group timers fire after stop** (`perf.ts:150–175`). Keep the ids and clear them
  on stop.
- `onPanic` (`engine.ts:1272`) has no unsubscribe. Return one (`Set`), as `onChannel` does.
- `ticker.ts:29`: a second `startTicker` re-posts the interval and the last caller wins. Today
  both callers use 20 ms. Post it once.
- `looper.ts:148`: `pageDuration(…, project.bpm)` after an overdub ignores the tempo map. Use
  `tempoNow()`, which the recording itself used.
- `render.ts:54`: offline `cycle` is the repeat index, while live it's the section's cumulative
  play count. **Verify** that conditions like `2:4` on a section with repeats (or clones) render
  the same as they play. If they don't, exports differ from playback. A unit test on
  `conditionPasses` over a song decides it.
- `physical.ts:28–37`: `seedPhysical` is never called, so offline renders of physical models
  aren't seeded per processor (D98 seeds `Math.random` only). Renders are deterministic only as
  long as the processors in one context run in the same order. Call it from the worklet's seed
  path.
- `physical.ts:167`: `bodyL`/`bodyR` hold exactly 6 biquads, and `BODY_MODES.piano` has 6. A 7th
  mode would write out of bounds silently. Size them from the largest body.
- `node.ts:131–133`: `panic()` drops queued `on`/`off`/`macros` but keeps `automate` messages
  queued before the node exists, which replay on the next start. Drop `automate` too, and keep
  only the latest `automateEnd`.
- `BeatboxPanel.tsx:420–436`: `SoundsPrompt`'s async `tick` can schedule a frame after unmount
  (the first `await import(...)`). Add an alive flag.
- `BeatboxPanel.tsx:62`: `loadModel().catch(() => {})`. A model that fails to load (offline,
  WASM blocked) shows nothing. Surface it in the Model view.
- `projects.ts:133–135`: if the last project fails to reopen, there's only a `console.error`.
  Show a toast so it's known.
- `PianoRollPanel.tsx:373`: `patterns[pattern.id].lanes` in pointer-up throws if the pattern went
  away mid-drag (undo). Use optional chaining and end the gesture.
- `Keyboard.tsx:73–79`: notes held while the octave changes are never released. Release them when
  `low` changes.
- `LibraryPanel.tsx:207–218`: an uncancelled rAF in an effect (harmless today). Return a cleanup.
- `electron/main.cts:186,238`: the IPC handlers don't check `e.senderFrame.url` (sandbox and
  context isolation already limit this). Add a one-line `rebeat://` check as defense in depth.
- `MiniLab3Svg.tsx:355–358`: flash timers are only cleared on unmount.

## 7. Suggested order

1. **Bugs, one commit each** (§1 #1–7, #12–15; §4's controller pruning, SysEx swap,
   `pointercancel`, tape-stop and mute timers). Each is a few lines plus a unit test where the
   logic is pure (redo guard, `lanePoints` cache, Mackie note-off via `midi/`).
2. **Hot paths**: the synth DSP allocations (#10, then events and drift), the knob-list cache
   (#8), the whole-store subscriptions and `TrackRow` (#9), and MIDI's per-message state (#11).
   Check them with the CPU meter (`engine/load.ts`) and React DevTools' profiler. The golden
   levels must stay identical (none of these should change the sound; if a golden moves, it's a
   bug).
3. **Dead code** (§5), one commit.
4. **Duplication** (§3), helper by helper, each one commit. Start with clone, path get/set,
   `sha256`, `clamp` and the size hook.
5. **Splits**: `SynthEditorPanel.tsx`, and `STEPPED` out of `midi.ts`.
6. **Startup and library I/O** (§2), measured with a bundle visualizer and the Performance tab
   before and after.
7. **Tooling** (§6) last, since the new lint rules will flag work from the steps above.

Run the full verification (AGENTS.md §2) after each step.
